# 10-08 사진 130장을 선행 개발자 측정 엔진으로 돌려 봄 (10-11)

엔진 = 선행 엔진 `shaft_core.py` (선행 개발자 measurement_engine.py 이식, 원본 464.0575px 재현 확인 통과)
실행: `conda run -n aiffel python run_engine.py` -> `run_tight.py` -> `summary.py` / 그림 `draw_edges.py`

## 결과
1. YOLO(demo_yolo11n_20260917.pt): 10-08 사진 13장 중 0장 검출. 09-16 구도로 학습한 모델이라 그대로는 못 쓴다 -> 측정 박스는 직접 지정(x = 사진마다 찾은 베어링부, y 3600~4320)
2. 원본 옵션 그대로(박스 위아래 40% 넓힘 + 가장 바깥 엣지 쌍): 위쪽 검은 가림막 경계(y 약 3465)와 아래 배경 경계를 집어 샤프트를 776px 로 읽음(실제 약 544). 에러·경고 없음 = 09-12 NG01 과 같은 조용한 실패
3. 박스를 안 넓히면(E) 원본 규칙도 안정된다. 다만 아래 경계의 바깥 단을 집어서 내 방법보다 약 +12px, 핀 +7.5px
4. 아래 경계는 밝기 단이 2~3개(4222, 4228, 4235 부근). 위 경계는 단 하나. 어느 단을 엣지로 보느냐에 따라 6~13px(220~480um) 달라진다. "가장 센 쌍"은 시편마다 다른 단을 골라 NO4 에서 +9px 튐
5. 오차표 (um, 10장 평균, 핀 Ø10 비율 + 교정 시편으로 치우침 빼기)

| 방법 | 같은 시편 흔들림 | 교정 4,5,6 -> 랜덤 7~10 MAE / 최대 | NG1, NG2 |
|---|---|---|---|
| A 원본 그대로 | 1002 | 6626 / 6782 | 못 씀 |
| E 원본 규칙, 박스 안 넓힘 | 37 | 19.8 / 28 | +13, +19 |
| F 가장 센 쌍, 박스 안 넓힘 | 12 | 97.9 / 113 | -51, -25 |
| M 내 방법 (50% 밝기) | 9 | 14.2 / 34 | +48, +71 |

전체(교정 나누기 3가지)는 `_out/summary.txt`. 어느 방법도 공차 ±10um 안에 못 들고, NG 를 정상과 가르지 못한다
