# 1011_mentor — 멘토 자료에서 건질 것 두 가지를 실제로 돌려봄 (2026-10-11)

데이터는 10-08 본촬영 130장(시편 13묶음 x 10장)이다. 규칙은 돌리기 전에 정했다.
- 시편 묶음 단위 2겹: 홀수 묶음으로 학습하고 짝수로 시험, 그 반대도.
- 같은 시편의 사진이 학습과 시험에 섞이지 않게 했다.

## 실험 1 — 증류 이상 탐지 (`ad/`)

멘토가 준 코드(Salehi 외 2021)를 지금 torch로 옮겼다(`ad/kdad.py`). 구조·손실·점수는 원본과 같다.
- 선생: VGG16(고정).
- 학생: 원본 cfg 'B'.
- 설정: λ 0.5, 300 epoch, 정상 사진만으로 학습.
- 보는 해상도 2가지:
  - 넓게: 1024px를 256으로 줄임, 1px = 약 148µm
  - 좁게: 위 경계 중심 512px를 256으로 줄임, 1px = 약 74µm

### T1. 진짜 NG(실측이 규격 하한 아래, 정상 평균보다 17~26µm 작음)를 가르나 — 못 가른다

(처음에는 NG를 "지름 +50~70µm 큰 불량"으로 적었는데 틀렸다. 그 숫자는 측정 오차였다. 실험 자체는 NG 묶음 사진을 그대로 써서 결과는 그대로다.)

| 보기 | A겹 AUC | B겹 AUC |
|---|---|---|
| 넓게 | 0.28 | 0.41 |
| 좁게 | 0.59 | 0.52 |

AUC 0.5가 동전 던지기다. NG 점수는 정상 묶음들 점수 범위 안에 있다. 예상대로다. NG가 두 시편뿐이라 AUC 자체도 많이 흔들린다.

### T2. 초점 구간(F1·F2 vs F3)에 따라 점수가 갈리나 — 겹마다 방향이 다르다

| 보기 | A겹 | B겹 |
|---|---|---|
| 넓게 | 0.50 | 0.25 |
| 좁게 | 0.76 | 0.36 |

"초점 바꾼 사진을 이상으로 잡을 것"이라는 내 예상은 일관되게 맞지 않았다. 갈리는 겹도 있지만 방향이 반대로 나온다. 예상이 틀린 것으로 기록한다.

### T3. 인공 결함 — 경계 결함은 잡는다

시험용 정상 사진에 원본 해상도로 결함을 그린 뒤 줄였다. 같은 사진의 깨끗한 판과 비교한 AUC이고, 괄호 안은 히트맵 최대점이 결함 자리(256 기준 16px 안)에 온 비율이다.

| 결함 | 크기 | 넓게 148µm (A / B) | 좁게 74µm (A / B) |
|---|---|---|---|
| 위 경계 패임 | 0.1mm | 0.55 / 0.54 | 0.59 / 0.58 |
| | 0.2mm | 0.66 / 0.65 | 0.76 / 0.71 |
| | 0.5mm | 0.79 / 0.85 | **0.97 / 0.91** (80% / 42%) |
| | 1.0mm | 1.00 / 1.00 | 1.00 / 1.00 |
| 위 경계 돌기 | 0.1mm | 0.57 / 0.56 | 0.77 / 0.72 |
| | 0.2mm | 0.75 / 0.79 | **0.92 / 0.86** (98% / 85%) |
| | 0.5mm | 0.97 / 0.96 | 1.00 / 1.00 |
| 표면 긁힘(3mm 길이, 주변보다 80 밝게) | 폭 0.05mm | 0.65 / 0.70 | 0.83 / 0.81 |
| | 0.1mm | 0.73 / 0.80 | 0.87 / 0.87 |
| | 0.2mm | 0.82 / 0.86 | 0.93 / 0.91 |

- **경계에 생긴 0.2~0.5mm 결함부터 잡힌다.** 해상도가 좋을수록 잘 잡는다(좁게가 넓게보다 확실히 낫다). 원본 해상도로 조각을 나눠 넣으면 더 작은 것도 잡을 가능성이 있다.
- 긁힘은 AUC는 높지만 위치 맞춤이 낮다. 기준이 16px인데 3mm 긁힘이 좁게 보기에서 40px 길이라, 히트맵 최대점이 긁힘 끝에 오면 빗나감으로 센다. 이 기준이 긁힘에는 불리하다.
- 그림: `_out/ad_heatmaps.png`. 넓게 보기의 히트맵은 결함이 없어도 **아래 경계(여러 단 반사)**와 단 모서리에서 뜨겁다. 정상 안에서도 원래 흔들리는 자리라는 뜻이다.

### 한계
- 결함은 그려 넣은 것이다. 진짜 긁힘·찍힘은 이보다 흐리고 모양도 다양하다.
- 이 조명(뒤에서 비춤)에서는 표면이 거의 검게 나온다. 진짜 표면 긁힘은 이렇게 밝게 보이지 않을 수 있다. 표면 검사를 하려면 앞 조명이 따로 필요하다.
- 시편 13개, 사진은 사실상 13가지뿐이다.

## 실험 2 — 측정 위치 찾는 경량 모델 (`pos/`)

- 모델: yolo11n(가장 작은 판), 입력 1280, 80 epoch, 위치·크기 흔들기 크게.
- 라벨: 사진마다 찾아둔 베어링부(x0~x1, 샤프트 위아래)와 핀 몸통.

| 시험 | 장수 | 베어링부 찾음 | 핀 찾음 | 베어링부 가장자리 오차 (중앙 / 최대, 원본 px) | 핀 오차 (중앙) |
|---|---|---|---|---|---|
| A→B 같은 구도 | 60 | 60 | 60 | 4.4 / 11.1 | 4.6 |
| B→A 같은 구도 | 70 | 70 | 70 | 4.7 / 10.4 | 7.8 |
| A→B 옮긴 사진(0.7~1.3배, ±25%) | 60 | 60 | 60 | 5.1 / 14.1 | 5.8 |
| B→A 옮긴 사진 | 70 | 70 | 70 | 5.7 / 9.4 | 7.1 |
| 09-16 다른 날·다른 구도(신뢰도 0.1까지) | 17 | 0 | 0 | — | — |

- CPU 한 장 추론: 0.045초. 이 데스크톱 기준이고 노트북은 더 느리다.
- 기존 YOLO(`demo_yolo11n_20260917`)는 같은 B세트 60장 중 34장에서 무언가를 잡았다. 맞는 자리인지는 확인하지 않았다. 이전 실행(원본 해상도, 엔진의 `detect_box`)은 0/13이었다. 입력이 달라 숫자가 다르다.

### 모델 상자로 지름을 재면 라벨 상자와 얼마나 다르나
- 중앙값 1.2~1.5µm다. 측정에 거의 영향이 없다.
- 예외는 **NO1·NO2 20장**이다. +16~63µm 차이가 났다.

### NO1·NO2 예외에서 새로 알게 된 것: 핀의 어느 열을 재느냐에 따라 핀 px가 바뀐다

- NO1·NO2에서는 핀이 실제로 왼쪽으로 놓여 있었다(`_out/pinchk.png`). 고정 라벨이 이걸 반영하지 못했다.
- 그래서 모델 상자 중심이 라벨보다 약 36px 왼쪽이었다.
- 10-08 NO1 첫 장에서 핀 열을 20px씩 옮기며 측정했다:

  ```
  x 9560~9680: 269.2 ~ 270.1px
  x 9700:      270.8px  (오른쪽 V블록 끝 그림자에 가까워질수록 커짐)
  x 9720 이후: 341px 이상 (V블록 끝과 붙음)
  ```

- 핀 px 1px는 Ø20에서 약 75µm다. 그러니 **핀을 재는 열이 V블록 끝에서 얼마나 떨어졌는지가 오차의 한 원인**이다.
- 10-08 분석은 열 9655\~9700으로 고정해서 쟀다. 그래서 핀이 놓인 자리가 바뀌면 V블록 끝과의 거리도 바뀐다. 앞서 "같은 초점 안에서도 핀이 269.08\~270.22px로 오갔다"고 한 것의 일부가 이것일 수 있다.
- 사진 한 장으로 본 것이라 확인이 더 필요하다.

### 결론
- **같은 구도·같은 날 안에서는 경량 모델이 위치를 잘 찾는다.** 카메라를 옮긴 것처럼 꾸민 사진에서도 잘 찾는다.
- **다른 날 다른 구도(09-16)는 하나도 못 찾는다.** 09-16으로 학습한 기존 YOLO가 10-08에서 못 찾은 것과 같은 구조다. 구도마다 사진 몇십 장을 라벨링해 다시 학습해야 한다. 지그를 고정하면 이 일이 줄어든다.

## 파일
- `ad/kdad.py`: 멘토 코드 이식
- `ad/cache.py`: 사진 자르기
- `ad/run.py`: 실험 1 본체
- `ad/fig.py`: 히트맵 그림
- `pos/prep.py`: 데이터셋 생성
- `pos/train.py`: 학습
- `pos/evaluate.py`: 평가
- `_out/ad_result.json`, `_out/pos_result.json`: 결과
- 로그·그림: `_out/`
- `_data/`·`runs/`는 다시 만들 수 있어 백업에서 뺐다.
- 버그 기록: `run.py` 1차 실행은 히트맵 그림용 결함 자리를 마지막 장 것으로 저장했다. 위치 맞춤 숫자는 사진마다 따로 계산해서 영향이 없다. 코드는 고쳤고, 그림에서는 표시를 뺐다.
