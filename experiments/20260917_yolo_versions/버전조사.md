# YOLO 버전 조사 — 이 프로젝트(측정부 위치 찾기, 1클래스, 정지 사진, 실루엣)에 무엇이 맞나 (2026-09-17)

현재 모델: **YOLO26n** (선행 개발자 확인, best.pt train_args: yolo26n.pt · imgsz 640 · 100 epoch · batch 4 · 7월 데이터 30장 = 원본 6장 + 증강). 학습 데이터 원본은 저장소에 없음(README만).
설치: ultralytics 8.4.75 (v3·v5·v6·v8·v9·v10·11·12·26·RT-DETR 지원), torch 2.9 ROCm, GPU 사용 가능.

| 버전 | 나온 때 | 특징 | 이 과제에서 기대 | 우려 |
|---|---|---|---|---|
| YOLOv8 | 2023 | 앵커프리, C2f, NMS 필요. 가장 널리 검증됨 | 기준선. 작은 데이터에 안정 | 최신보다 느림 |
| YOLOv10 | 2024 | **NMS 없는 end-to-end** 첫 도입, 이중 라벨 할당 | 1클래스 1객체라 NMS 이득은 없음 | 소규모 데이터 수렴 느릴 수 있음 |
| YOLO11 | 2024-09 | C3k2·C2PSA(어텐션), v8 대비 파라미터 적고 mAP 높음 | 균형. 많이 쓰임 | — |
| YOLO12 | 2025 | 어텐션 중심(area attention, R-ELAN) | 큰 문맥(칼라·홈 위치 관계)에 유리할 수 있음 | 학습 무겁고 소규모 데이터에서 불안정 보고 |
| **YOLO26** | 2026 초 | NMS 없음 + DFL 제거 + ProgLoss/STAL(작은 물체) + MuSGD. CPU 43% 빠름 | 폰·엣지 배포에 유리. 지금 모델 | 새 버전이라 검증 사례 적음 |
| RT-DETR | 2023 | 트랜스포머 검출기, NMS 없음 | 정확하나 무겁고 데이터 많이 필요 | 91장으로는 과적합 위험 → 이번엔 제외 |

## 이 과제의 특수성
- 1클래스, 사진당 1객체, 배경 단순(실루엣), 위치가 거의 고정 → "검출 난이도"는 낮고, **박스 경계가 얼마나 일정한가**(높이·위치 sd)와 **조건이 바뀌어도(원본 해상도·백라이트) 무너지지 않는가**가 관건
- 09-17 확인: 측정 창을 20px 옮겨도 정상품 3µm 이하 → 버전이 **측정 정밀도**를 바꿀 가능성은 낮음. 바꿀 수 있는 것은 검출 안정성(S07 conf 0.25, 원본 5/14 붕괴)
- MQ02(풍력 터빈) 경험: 5개 세부 모델 각자 장점 → 앙상블. 다만 그건 다중 클래스·결함 검출이었고 여기는 박스 1개 회귀에 가까움

## 실험 설계 (실측이 추론과 다를 수 있으니 돌린다)
- 데이터: 9/16 161장 2992, **프로파일 자동 라벨**(칼라끝·홈·윗변·아랫변에서 박스 생성, 기존 YOLO 박스 규약에 맞춤). 시편 단위 분할 train 7시편 91장 / val 6시편 70장 (누수 없음)
- 학습: v8n·v10n·11n·12n·26n + 26s·11s, 60 epoch·640·batch 8·seed 0 동일
- 평가(val 70장): 검출률 · IoU(자동 라벨 대비) 중앙/최소 · conf · 박스 높이 시편내 sd · **측정 px 시편내 sd**(박스를 측정기에 넣어) · 6008 원본 투입 시 붕괴 장수
- 앙상블: n 5종 박스 conf 가중 평균
- 기준선: 기존 best.pt(7월 학습 26n)
- 성공 기준: val 검출 70/70, IoU 중앙 ≥ 0.8, 측정 px sd가 기존 파이프라인(0.06 ~ 0.21px)과 같거나 작음, 원본 붕괴 0/14
- 한계: 자동 라벨은 "정답"이 아니라 프로파일이 잡은 경계다. IoU는 절대 정확도가 아니라 **일관성** 지표로 읽는다. 학습 데이터가 한 세션(9/16)이라 조건 일반화는 못 잰다
