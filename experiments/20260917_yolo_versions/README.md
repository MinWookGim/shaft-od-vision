## 읽기
1. **측정 정밀도는 버전과 무관하다.** 측정 px 시편내 sd 0.112 ~ 0.128px — 8개 모델이 한 묶음, 기존 파이프라인(0.06 ~ 0.21)과 같은 급. 09-17 낮의 "창 20px 옮겨도 3µm 이하"와 일치. 예측이 실측으로 확인됨
2. **S07 conf 붕괴(0.27)는 아키텍처가 아니라 학습 데이터 조건 문제였다.** 같은 9/16 조건으로 재학습하면 어떤 버전이든 0.78 ~ 0.97. → claims C2 닫힘. 백라이트 조건 데이터로 재학습이 타당하다는 근거
3. **6008 원본 붕괴는 YOLO 박스 탓이 아니다.** 8개 모델 전부 원본에서 박스 높이가 기대의 ±15% 안(이상 0/14). 붕괴는 측정기의 허용 지름 범위(파라미터)가 해상도에 안 맞아서 생긴 것 — 09-16 심야 결론과 일치. 2992 축소는 그걸 우회하는 방법
4. **앙상블은 박스가 가장 일정하다**(높이 sd 0.54, IoU 0.970)지만 측정 sd는 안 줄었다. 박스 흔들림 0.5 ~ 2px는 측정부가 평평해 값에 안 실린다. MQ02(다중 클래스 결함 검출)와 달리 여기는 박스 1개 회귀라 앙상블 이득이 측정값까지 안 간다
5. YOLO26 계열은 conf가 시편마다 고르지 않다(26s S10 0.52). NMS-free 모델의 conf 보정이 소규모 데이터에서 덜 안정한 것으로 보임(관찰). conf를 "검출 신뢰도 문턱"으로 쓰려면 11n이 가장 고르다
6. 결론: 버전 선택은 정밀도 문제가 아니라 **운영 문제**(conf 문턱 안정성 · 배포 속도). 후보 = yolo11n(conf 고름) 또는 yolo26n(배포·속도, 지금 모델). 앙상블은 비용 대비 이득 없음
