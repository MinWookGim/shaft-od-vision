# 코드 수정 방향 7가지 적용 결과 (10-08 사진) — 2026-10-12

10-12 오전에 선행 개발자가 자료실에 올린 "코드 수정 방향 7가지"를 10-08 사진에 적용해 본 결과다. 7가지는 샤프트 표면의 밝은 반사띠가 경계로 잘못 잡히는 것을 막으려는 전처리다.
전체 분석 흐름은 [2차 촬영 분석 정리](./2026-10-12_2차촬영_분석정리.md) 5절에 있다.

---

### 1. 7가지 (원문)
| 번호 | 기법 | 하려는 것 |
|---|---|---|
| 1 | threshold / inRange | 밝은 띠 제거 |
| 2 | morphology OPEN · CLOSE | 좁은 띠 제거 |
| 3 | MORPH_TOPHAT | 밝은 띠 찾기 |
| 4 | MORPH_BLACKHAT | 어두운 띠 찾기 |
| 5 | connectedComponentsWithStats | 띠 영역을 덩어리로 묶어 제거 |
| 6 | contour 폭·높이 조건 | 띠 모양(가로로 길고 얇음)만 고르기 |
| 7 | ROI 내부 Reflection Mask | 샤프트 가운데 반사띠 가리기 |

### 2. 어떻게 돌렸나
- **엔진**: 선행 엔진을 "가장 센 엣지 쌍, 박스 안 넓힘"으로 설정. 선행 결과보고서 px를 0.1px 안에서 재현하는 설정이다(NO4/5/6 = 550.43/544.89/543.33, 보고서 550.33/544.86/543.26)
- **전처리 값**: 원문에 커널 크기와 문턱이 없어서 팀장이 정했다. 결과를 보기 전에 고정했다
  - 세로 커널 25px: 이보다 얇은 띠를 지운다. 샤프트 아래 회색 선반(약 40px)은 건드리지 않는 크기
  - TOPHAT 문턱 밝기 25
  - 1 inRange: 샤프트 안쪽(위·아래 경계에서 10px 들어간 곳)에서 하위 10% 밝기 + 30보다 밝은 화소를 그 어두운 값으로 바꾼다
  - 3은 원본 − TOPHAT(= OPEN), 4는 원본 + BLACKHAT(= CLOSE)으로 적용했다. 그래서 3은 2와 결과가 같다
  - 5·6은 하나로 묶었다: 밝은 띠 중 가로 폭이 박스의 30% 이상이고 높이가 25px 이하인 것만 지운다
  - 7은 샤프트 지름의 가운데 25~75% 줄을 어두운 값으로 덮는다
  - "전부"는 1 -> 5·6 -> 2 -> 7 순서로 겹쳐 적용
- **측정 위치**: 베어링부 자동 탐지 박스. 아래 5절에서 선행 개발자의 박스(고정, Anchor 추적)로도 다시 돌렸다

### 3. 평가 세 가지
- **(가) 선행 절차**: NO4~6 3점으로 교정 직선을 만들고 NO7~10 검증 MAE. 시편마다 10장을 평균한 뒤 시편 4개로 MAE를 냈다(보고서 2.34µm는 40장 각각의 MAE라 계산 방식이 조금 다르다). NG1·NG2도 10장 평균으로 규격 20.010~20.030 판정, NG 20장 중 OK 수는 사진 한 장씩 판정
- **(나) 같은 나누기의 평균 찍기**: 측정 없이 20.020만 출력해도 (가)에서 MAE 3.5µm, 40/40 OK. (가)는 이것과 같이 봐야 한다
- **(다) 핀 고정 LOO**: 핀으로 mm 환산, 정상 10개를 하나씩 빼며 교정. 평균 찍기는 5.8µm

### 4. 결과 (베어링부 박스)
| 변형 | NO4/5/6 px | 교정 기울기 µm/px | (가) 검증 MAE µm | NG 20장 중 OK | (다) 핀 고정 LOO µm |
|---|---|---|---|---|---|
| 원본 (적용 전) | 550.43 / 544.89 / 543.33 | 2.55 | 2.1 | 20 | 50.6 |
| 2 OPEN · CLOSE | 550.29 / 544.55 / 543.23 | 2.50 | 2.0 | 20 | 52.4 |
| 3 TOPHAT | 550.29 / 544.55 / 543.23 | 2.50 | 2.0 | 20 | 52.8 |
| 4 BLACKHAT | 550.43 / 544.77 / 543.36 | 2.53 | 2.0 | 20 | 51.2 |
| 5·6 덩어리 · 크기 | 550.43 / 544.82 / 543.33 | 2.53 | 2.0 | 20 | 52.6 |
| 7 중앙 mask | 550.43 / 544.89 / 543.33 | 2.55 | 2.1 | 20 | 50.6 |
| 1 inRange | 532.20 / 532.63 / 543.32 | -1.40 | 10.0 | 0 | 199.3 |
| 전부 | 532.19 / 532.47 / 543.21 | -1.40 | 9.7 | 0 | 192.4 |
| (기준) 평균 찍기 | | | 3.5 | 20 | 5.8 |

- **2~7은 px가 최대 0.34px만 바뀌고 결과도 그대로다.** (가) MAE 2.1 -> 2.0, NG 20장은 전부 OK 그대로. 측정하는 것은 샤프트 바깥 외곽인데, 띠 제거는 외곽을 건드리지 않는다. 가운데 반사띠는 처음부터 경계로 잡히지 않았다
- **1 inRange와 "전부"는 NG를 NG로 본다. 하지만 정상 NO7~10도 전부 NG(약 20.006)다.** 아래 회색 선반이 지워져 NO4 경계가 약 18px, NO5가 약 12px 안쪽으로 갔고 NO6는 그대로라 교정 기울기가 음수가 됐다(지름 px가 클수록 mm가 작다는 식). 출력 전체가 20.020 근처에서 20.006 근처로 옮겨 간 것이지 NG를 구별한 것이 아니다
- (다)에서는 어느 변형도 평균 찍기 5.8µm에 한참 못 미친다

### 5. 선행 개발자 박스로 다시 (고정 박스 / Anchor 추적)
- 박스 = 선행 보고서의 REFERENCE_BOX (7844, 3468, 8089, 4468)
- Anchor = 박스 주변(x 7400~8500, y 3200~4700) template matching, ±200px 탐색. 탐색 영역과 범위는 팀장이 정했다. 매칭 점수(시편별 중앙값) 0.97~1.00
- 박스 높이가 1000px라 샤프트 허용 지름 범위를 박스의 0.40~0.70으로 바꿨다

| 박스 | 변형 | NO4/5/6 px | (가) 검증 MAE µm | 정상 40장 OK | NG 20장 중 OK |
|---|---|---|---|---|---|
| 고정 | 원본 | 550.41 / 544.96 / 543.35 | 2.2 | 40 | 20 |
| 고정 | 7 중앙 mask | 550.41 / 544.96 / 568.82 | 5.6 | 37 | 9 |
| 고정 | 1 inRange | 532.19 / 532.72 / 649.31 | 10.1 | 0 | 0 |
| 고정 | 전부 | 532.19 / 532.57 / 569.62 | 5.5 | 18 | 0 |
| Anchor | 원본 | 550.46 / 544.85 / 543.32 | 2.2 | 40 | 20 |
| Anchor | 2 OPEN · CLOSE | 550.31 / 544.51 / 543.22 | 2.0 | 40 | 20 |
| Anchor | 7 중앙 mask | 550.46 / 544.85 / 543.32 | 14.2 | 30 | 20 |
| Anchor | 1 inRange | 532.23 / 532.61 / 543.32 | 9.9 | 10 | 0 |
| Anchor | 전부 | 532.23 / 532.47 / 543.20 | 16.4 | 0 | 0 |

측정 실패: 고정 + 전부 3장, Anchor + 전부 2장. 나머지는 0장. 고정 + OPEN·CLOSE는 MAE 2.0, 40 / 20으로 원본과 같다

- 원본은 베어링부 박스, 고정 박스, Anchor 세 가지가 px 약 0.1px 안에서 같다. 샤프트가 가로로 누운 원통이라 박스가 옆으로 밀려도 지름이 거의 안 바뀐다
- 위치에 따라 동작하는 7(중앙 mask)과 1(inRange), 그리고 둘이 들어간 전부는 고정 박스에서 NO6 px가 568~649로 크게 틀어졌다. Anchor를 쓰면 이렇게 틀어지지는 않았다. 다만 결과는 원본보다 나빴다

### 6. 정리
- 이번 구현으로는 10-08 사진에서 반사띠 제거가 결과를 거의 바꾸지 않았다
- 선행 개발자 중간보고서 초안(10-12) 5.2절: "NO4~NO10 데이터에서는 Reflection Mask가 대부분 실제 측정결과에 영향을 주지 않았으며 V2와 동일한 결과가 다수 발생". 같은 방향이다. 초안은 Reflection Mask를 앞으로 촬영 조건이 바뀔 때를 위한 안전장치로 유지한다고 판단했다
- 오차가 남는 곳은 샤프트 아래 경계다. 아래 경계는 여러 단으로 나뉘고(백라이트 빛 넘침으로 추정, 원인 미확인), 어느 단이 실제 표면인지 사진 안에 근거가 없다([분석 정리](./2026-10-12_2차촬영_분석정리.md) 4절). 전처리로 단을 지우면(inRange) 경계가 통째로 옮겨 간다

### 7. 약한 곳 · 남은 것
- 커널·문턱·Anchor 영역은 팀장이 정한 값이다. 선행 개발자의 실제 코드와 다를 수 있다. 선행 개발자 코드로 같은 표를 다시 만들어 맞춰 볼 것
- 원문 docx 끝의 숫자(Bias·MAE +0.002343, 최대 0.004647, 40/40)가 V2 보고서와 소수 여섯째 자리까지 같다. 7가지 적용 후 결과인지 확인이 필요하다
- 데이터는 10-08 한 번이다. 촬영 조건(아래 경계 빛)이 바뀌면 결과가 달라질 수 있다
