# 라이브 시연 계획 — 2026-09-21 구글밋

## 한 줄
폰으로 집의 NG 샤프트를 찍어 올리면, 공유 중인 맥 화면에 3초 뒤 **지름 mm와 판정**이 뜬다. 같은 자리에서 두세 장 더 올려 **프레임 간 흔들림 sd(µm)** 가 그 자리에서 계산되는 것까지 보인다.

## 구성

```
[폰: 기본 카메라 앱, 최고 해상도, 2배, 자동]  → 갤러리에서 선택
      │ Tailscale
      ▼
[우분투: demo_app.py, Streamlit 8512]  ── 2992 축소 → YOLO 위치 → OpenCV 31열 서브픽셀 → px → mm → 3단 판정 → results.jsonl
      ▲ Tailscale                                      │
[맥: 브라우저 ?view=screen, 2초마다 새로고침] ◀─────────┘   ← 이 창을 구글밋에 화면 공유
```

- 폰 주소 `http://100.119.195.56:8512` (업로드·배율 잡기)
- 맥 주소 `http://100.119.195.56:8512/?view=screen` (청중용. 큰 숫자 + 판정 + 검출 박스 그린 사진 + 세션 반복 표)
- 서비스 `shaft-demo`(systemd user). `systemctl --user start shaft-demo`. 로그 `field/logs/demo.log`
- Tailscale: 맥(m1s-macbook-pro) 활성 확인. **폰(s26-ultra)은 1일 전 오프라인 → 리허설 전에 폰 Tailscale 켜기.**

## 순서 (60~75초, 11장 뒤 또는 Q&A)
1. (5초) "지금 제 책상에 있는 NG 시편입니다." 맥 화면 = 청중 화면, 아직 빈 상태
2. (15초) 폰으로 한 장 찍어 갤러리에서 올린다
3. (5초) 화면에 사진 + 박스 + **mm** + **불합격(확정)** + "공칭 대비 +NNN µm"
4. (20초) 같은 자리에서 두 장 더 → "이 세션 3장 · 흔들림 sd N µm" 표가 채워진다. "카메라는 안 흔들립니다. 오늘 오차 세 층 이야기의 c층이 이겁니다"
5. (10초) 배율 캡션 가리키며 한 문장: "배율은 이 세팅에서 실측값으로 한 번 잡아 둔 값입니다. 핀게이지가 오면 이 자리가 2점 캘리브레이션이 됩니다"

## 정직성 — 반드시 말할 것
- 배율은 **1점 캘리브(집 시편 실측값)** 다. 그래서 이 시편의 mm는 정의상 실측값 근처로 나온다. 시연이 보여주는 건 **파이프라인이 살아 있음 + 반복 정밀도**이지, 절대 정확도가 아니다.
- 규격 안으로 찍히는 값은 지금 정밀도(sd 17)에선 전부 회색지대다. 앱도 그렇게 표시한다.
- 집 시편은 검정 코팅에 하이라이트 띠가 있어 팀 파이프라인이 같은 프레임에서 7µm쯤 흔들린다(9/18). 1µm가 아니라 5~10µm가 떠도 정상. "현장 시편(무코팅)에선 2~7µm"라고 덧붙인다.
